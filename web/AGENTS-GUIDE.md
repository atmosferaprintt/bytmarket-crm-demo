# Как делать раздел БытМаркет CRM

Общие правила для всех, кто пишет разделы в `web/`. Читать целиком перед работой.

## Что это
Интерактивное демо CRM для рознично-оптового магазина бытовой химии в Астрахани. Его покажут владельцу магазина: традиционалисту, который любит понятные таблицы и минимум лишних действий. Всё должно выглядеть законченным и живым на правдоподобных данных. Пустой экран выглядит сыро.

Стек: React 18, TypeScript strict, Vite 5, react-router-dom 6 (HashRouter), lucide-react. Без других библиотек; `package.json` не меняй.

Dev-сервер уже запущен владельцем работ: `http://127.0.0.1:5173`. Свой сервер не запускай.

## Папки и владение
- `src/ui/` — детали: `Button, Input, Select, SearchInput, QtyInput, MoneyInput, Checkbox, Field, Chip, StatusChip, Card, Kpi, StatList/StatRow, EmptyState, Notice, ProgressBar, Steps, Avatar, IconTile, Tabs, RouteTabs, Segmented, Modal, Drawer, MoreMenu, ConfirmButton, DataTable, toast, fmt`, словарь статусов. Импорт только `from '../../ui'`. **Не менять.** Нужна новая общая деталь — сделай её у себя в папке и напиши об этом в отчёте.
- `src/ui/statuses.ts` — единые слова статусов: `ORDER_STATE, PICK_STATE, SHIP_STATE, PAY_STATE, overdueStatus(days), DELIVERY_STATE, PURCHASE_STATE, QUARANTINE_STATE, VISIT_RESULT, VISIT_STATE, PAYMENT_STATUS, STOCK_LEVEL`. Свои слова для тех же состояний не придумывай.
- `src/ui/format.ts`, через `fmt` — `fmt.money(12400)` → «12 400 ₽» (итоги и суммы), `fmt.price(137.5)` → «137,50 ₽» (цена за штуку), `fmt.moneyShort`, `fmt.num`, `fmt.pct`, `fmt.delta`, `fmt.qty`, `fmt.date` → «5 ноября», `fmt.dateShort` → «05.11», `fmt.time`, `fmt.dateTime`, `fmt.relDate(iso, today)` → «сегодня / вчера / 3 ноября», `fmt.daysBetween`, `fmt.addDays`, `fmt.count(n, 'заказ','заказа','заказов')`, `fmt.plural`, `fmt.phone`, `fmt.monthName`.
- `src/shell/` — меню, шапка, поиск, задачи, карточки сущностей. **Не менять.** Пользоваться можно:
  - `PageHeader` — `<PageHeader section="sales" actions={…} counts={{ returns: 3 }} />`: заголовок, вкладки раздела по роли и действия справа в одну строку. **Ставь его первым в каждом экране раздела.**
  - `EntityLink`, `useOpenEntity` — `<EntityLink type="order" id={o.id}>№ {o.number}</EntityLink>` открывает карточку в боковой панели поверх любого экрана. Типы: `order, client, product, purchase, supplier, delivery, receipt`.
  - `TaskModal` — `<TaskModal link={{ type: 'client', id }} onClose={…} />`.
- `src/roles/` — `useSession()` → `{ me, role, meta, can(perm), sees(section), discountLimit }`; `useScoped()` → `{ clients, orders, deliveries, visits, chats, receipts, myTasks, isMine }`, то есть данные в границах роли. Права: `src/roles/roles.ts`, тип `Perm`. **Не менять.**
- `src/data/` — модель (`types.ts`), генератор, операции, расчёты. **Не менять.** Пользоваться можно:
  - `useDB()` — вся база, перерисовка при изменениях; `getDB()`; `useDBVersion()` — для зависимостей `useMemo`, потому что база меняется на месте; `dispatch(type, payload, actorId)` → `{ ok, id?, info? } | { ok: false, error }`; `resetDemo()`; `nowDemo()`.
  - Перечень операций и их payload — `src/data/ops.ts`. Общие расчёты — `src/data/selectors.ts`: остатки, цены с акциями, оплата заказа, долг клиента, долги поставщикам, кассы, смена, продажи за период, периоды. Сначала ищи там, потом считай сам.
  - Сегодня — `db.meta.today` (5 ноября 2026), сейчас — `nowDemo()`.
- `src/sections/<раздел>/` — твоя папка. Входной файл `routes.tsx` (default export) рендерит `<Routes>` вкладок раздела относительно пути раздела: `<Route index …/>`, `<Route path="returns" …/>`. Файлы карточек и общих окон уже лежат заглушками. Сохрани их имена, экспорт и props: ими пользуются другие разделы. Остальное раскладывай внутри своей папки как удобно.

## Правила вида — за нарушения переделывают
- Шрифт Manrope уже подключён. Размеры только 11 / 12 / 13 / 14 / 16 / 20 / 24 / 32: классы `t-11…t-32` или `var(--fs-*)`. Начертание: `w-500 / w-600 / w-700`.
- Цвета только через `var(--…)` из `src/ui/tokens.css`. Своих hex и rgba нет. Свой CSS — в файле `<раздел>.css` в твоей папке, импорт из `routes.tsx`. Классы с префиксом раздела, например `.sales-…`, чтобы не задеть чужие.
- Цифры моноширинные: уже стоит на body, в таблицах `align: 'right'` для чисел. Суммы через `fmt.money` — без копеек в итогах.
- Иконки только lucide-react. Эмодзи и стрелки текстом («→», «↗») в интерфейсе не используй.
- Белые карточки (`Card`, `.card`), скругление 16–20, лёгкая тень. Цветных полосок слева, цветных рамок и залитых цветом плиток нет.
- Подписи обычными буквами: без КАПСА и разрядки. Заголовки таблиц — обычный регистр.
- Статус — текстом в чипе (`StatusChip`), цвет только помогает.
- Под числами нет серых пояснений. Подпись — над числом или в заголовке колонки. Пояснение, если оно правда нужно, — в подсказке `title` или в отдельном «Как считается» по кнопке.
- Метка «демо» одна, она в шапке. Слова «демо», «учебный», «тестовый» в тексте раздела не пиши. Всё выглядит как настоящая программа магазина. Касса пишет «Чек не фискальный: касса не подключена» только в одном месте окна оплаты — это честность, а не метка.
- **Одна главная кнопка на экране** (`variant="primary"`), обычно справа в `PageHeader`. Остальное — `secondary`, `ghost` и меню `MoreMenu`. В окне или панели одна главная кнопка в подвале.
- Таблицы — через `DataTable`: поиск, фильтры-таблетки со счётчиками, сортировка по заголовку, итоги в подвале (`total`), сохранённые виды (`id`), выгрузка для Excel (`exportName`). Строка кликается и открывает карточку.
- Удаление и отмена — через `ConfirmButton`: «Точно? Да / Нет» в самой кнопке, без отдельных окон.
- Тексты по-русски: коротко, по-человечески, без жаргона. Ошибки понятные: что не так и что сделать. Пустые состояния осмысленные: «Заявок нет — все подтверждены».
- Ширина: экран должен выглядеть хорошо на 1440 и на 1280. Без горизонтальной прокрутки страницы; широкая таблица прокручивается внутри своей карточки. Роли с телефоном (представитель, курьер) проверяются на 390 px: крупные кнопки, карточки вместо широких таблиц, главное видно без прокрутки вбок.

## Данные и действия
- Список для роли бери из `useScoped()`, а не из `db.*` напрямую, где есть ограничение: клиенты, заказы, доставки, визиты, чаты, чеки.
- Себестоимость, прибыль и маржу показывай только при `can('seeCost')` / `can('seeProfit')`. Кнопки действий — только при нужном праве. Роли без права кнопку не видят: ни выключенной, ни с замком.
- Любое изменение — `dispatch('order.confirm', { id }, me.id)`:
  - если `!r.ok` — покажи `r.error`: в окне через `Notice tone="bad"` или `toast(r.error, 'error')`;
  - при успехе — короткий `toast('Заказ подтверждён')`;
  - не меняй `db` руками.
- Производительность: 1000 товаров, около 3000 чеков, 500 заказов. Считай через `useMemo` с зависимостью `useDBVersion()`, используй индексы из `selectors.ts`, не делай `find` внутри `map` по большим массивам.

## Проверка — обязательно, до слова «готово»
- Браузер общий, им одновременно пользуются другие агенты. **Не переходи по адресам в общей вкладке.** Работай только через `mcp__playwright__browser_run_code_unsafe` в собственном контексте:
  ```js
  async (page) => {
    const ctx = await page.context().browser().newContext({ viewport: { width: 1440, height: 900 } });
    const p = await ctx.newPage();
    const errors = [];
    p.on('console', m => m.type() === 'error' && errors.push(m.text()));
    p.on('pageerror', e => errors.push(e.message));
    await p.addInitScript(() => localStorage.setItem('bm-session-v2', JSON.stringify({ employeeId: null, role: 'owner' })));
    await p.goto('http://127.0.0.1:5173/#/sales');
    await p.waitForTimeout(1500);
    await p.screenshot({ path: '/Users/rabiatsahrudinova/Documents/ChatGPT/срм быт дом/output/v2/sales/owner-1440.png', fullPage: true });
    await ctx.close();
    return errors;
  }
  ```
  Роль меняется ключом `bm-session-v2`: `{ employeeId: null, role: 'manager' }` — подставится первый сотрудник с этой ролью. Роли: `owner, seller, manager, rep, accountant, warehouse, dispatcher, courier`.
- Снимки клади в `output/v2/<раздел>/`. Смотри их через Read. Ищи огрехи: наложения, обрезанный текст, пустые места, слишком мелкое, лишние кнопки, нарушения правил вида. Исправляй и повторяй, пока не станет чисто.
- Проверь:
  - ширины 1440 и 1280, для телефонных ролей ещё 390 × 844;
  - каждую роль, которой виден раздел;
  - основные действия по-настоящему: нажать, заполнить, сохранить, увидеть результат;
  - консоль без ошибок.
- `npx tsc -p . --noEmit` из `web/` — твои файлы без ошибок. Чужие ошибки в чужих папках не трогай.
- Действия в браузере меняют журнал демо в `localStorage` твоего собственного контекста. Он закрывается — и всё пропадает. Это нормально.
